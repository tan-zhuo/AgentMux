# AgentMux

**面向远程主机上 AI 编程 agent 的桌面控制平面。**

[English](README.md) · 中文

![AgentMux](docs/demo.gif)

---

## 概述

AgentMux 用于运维在远程服务器上执行的编程 agent——Claude Code、Codex、Gemini CLI、
OpenCode、Aider、Cursor CLI 等。每个 agent 运行在目标主机的 `tmux` 会话中，应用连接到
该会话，而不持有进程本身。因此关闭客户端、休眠笔记本或网络中断，都不会影响正在进行的
工作。

它是单个二进制，没有服务端、没有守护进程、不需要账号。全部状态是应用数据目录下的一个
SQLite 文件。

## 能力

**会话持久化。** agent 在客户端断开后继续运行，这是结构决定的。重新打开终端会连回同一个
pane，滚动缓冲区完整保留——一个四小时的迁移任务不再依赖一条 SSH 连接不断。

![连到 agent 的终端](docs/terminal.png)

**直接的终端访问。** 每个 agent 的 pane 是完整终端——颜色、鼠标、选中、搜索——而不是
只读的会话记录。运维人员可以中途介入、纠正 agent，再把控制权交回去，无需重启任务。

**多个会话同屏。** 终端区可拆成最多四个窗格——两个或三个按任一方向划分，四个为 2×2
网格——每个窗格持有各自的会话，可以在同一台主机上，也可以分布在多台主机上，且各自独立
操作。窗格是视图而不是会话：关闭一个只是收起终端，其 shell 仍保持连接；窗格数量在下次
启动时恢复。填充窗格由一个对话框完成，其中列出可用的主机、工作区目录、正在运行的 agent
以及已打开的标签页——同时盯住两台服务器上的两个 agent，只需一个快捷键加一次选择，而不是
一场窗口管理练习。

**批量下发与送达回执。** 一条指令可以发给任意选中的 agent，每个返回一张回执，确认是否
真的送达。对集群的批量操作是可审计的，而不是假定成功。

![群发回执](docs/broadcast.png)

**本地编排，人工审批。** 通过 Ollama 提供的本地模型可以接受一个目标——例如查明某个
agent 为何停止推进。它读取集群状态、检索既有上下文，一次一个工具调用地推进。任何会修改
主机的操作都会被挂起等待显式审批，并展示工具名、参数、目标主机以及模型给出的理由。
破坏性操作在**所有**主机上都要确认，与该主机的信任级别无关。定时巡检被限制为只读工具。
编排能力默认关闭，需要运维人员主动启用。

**本地保留的检索记忆。** 项目事实、已声明的偏好、agent 活动都会被索引，支持按原文或按
语义检索。embedding 在本地生成，内容不出本机。匹配已知模式的凭据在入库前被脱敏——实际
风险在于同一个 token 会在之后每次命中检索时被重新提供给模型。

**可复用的操作程序。** 运维程序可以记录为技能：适用条件、步骤、涉及的工具与约束；条件
再次出现时会被自动匹配。由编排器提出的程序进入审核队列，未经批准不产生任何影响。

**主机初始化。** 安装面板会检查主机，只提供它确实能支持的 agent CLI 与运行时，并说明
其余为何不可用。安装过程在 `tmux` 中执行，连接中断不会留下不完整的包树。

![安装面板](docs/install.png)

**主机指标与文件访问。** 单条命令采集每台主机的指标——按模式与按核心的 CPU、内存、负载、
磁盘用量与吞吐、网络、文件描述符、NVIDIA GPU 利用率。基于同一条连接提供 SFTP 文件浏览
与编辑，写入是原子的，并带修改时间校验，拒绝覆盖同目录下 agent 所做的改动。

**界面。** 默认采用 Apple 系统配色，另提供六套主题，包括 Nord、Solarized 和亮色主题。

![主题](docs/themes.png)

## 适用场景

- **长时任务。** 迁移、重构、测试批次等跨越一个工作时段或一条网络链路的工作。
- **多主机集群。** 三到五十台主机上并发的 agent 活动，在一棵树里呈现状态与最新输出。
- **协同变更。** 一次操作向整个集群下发指令，并确认实际送达情况。
- **主机初始化。** 把一台新主机带到可用状态，无需手工拼装安装命令。
- **无人值守监控。** 定时只读巡检，报告已经停滞的 agent，但没有对其采取行动的权限。
- **受限环境。** 规划、embedding 与记忆全部在本地运行。AgentMux 不代理 agent 的模型
  流量，也不读取 agent 的 API key。

## 边界

明确写出来，因为这些决定了它是否是合适的工具：

- **一份安装对应一名使用者。** 状态、凭据与决策日志都在本机。没有共享服务端、没有团队
  账号、没有集中的审计汇聚点；两个人管理同一批主机时看到的是同样的 `tmux` 会话，但各自
  保留独立的历史。
- **不负责模型开销。** agent 的流量从主机直连它自己配置的服务商。AgentMux 既不代理也不
  读取其 key——这同时意味着它无法统计费用，也无法施加预算限制。
- **目标主机需为类 Unix 系统。** 每台主机都需要 SSH、POSIX shell 与 `tmux`。Windows 可
  以作为工作站，但不能作为目标主机。
- **它不决定 agent 做什么。** 目标、提示词与仓库约定仍属于使用者；编排器只做调查与提议，
  要动手就必须先获批。
- **构建未签名。** 由此增加的各平台额外步骤见「安装」一节。

## 安全模型

| 方面 | 行为 |
|---|---|
| 凭据 | 密码与密钥口令以 AES-256-GCM 加密后存储，主密钥保存在系统钥匙串中——凭据管理器 / Keychain / Secret Service。钥匙串不可用时退回 `0600` 文件，并在状态栏声明。 |
| 主机身份 | 主机密钥在首次连接时固定；后续不匹配将中止连接并说明原因。 |
| 前端暴露面 | 密钥不进入 UI 进程，界面只知道某项密钥是否已设置。 |
| 编排器权限 | 工具是固定白名单，绑定到既有服务；每个工具在声明处固定风险档。执行只能经由单一闸门，该闸门综合风险档、主机信任级别与本次运行的触发来源。 |
| 无人值守执行 | 定时运行无条件拒绝一切非只读工具，该限制不可配置。 |
| 不可信输入 | 远程主机的输出以带边界的数据块形式进入模型上下文并标注为数据；形似指令的文本会在审批卡片和决策日志中标记。 |
| 破坏性操作 | 在 AgentMux 里删除任何东西都不会终止远程工作：删掉工作区或 agent 记录，`tmux` 会话照旧运行。唯一会销毁运行中会话的控件叫 Kill，并且会先确认，并说明将失去什么。 |
| 可审计性 | 每次运行的每一步都被记录，包括被拒绝、被否决和无人应答的提议。 |

## 环境要求

远程主机需要 `tmux` 和 SSH 账号；缺少 `tmux` 时 AgentMux 可代为安装。本地编排与语义
检索另需 [Ollama](https://ollama.com) 及一个对话模型和一个 embedding 模型；没有它时
应用其余部分完全可用。

Linux 运行时需要 GTK3 与 WebKitGTK 4.1——Debian/Ubuntu 上为 `libwebkit2gtk-4.1-0`，
Fedora 上为 `webkit2gtk4.1`。macOS 需 11 及以上，Windows 需 10 及以上。

## 安装

每个 release 提供三个平台的构建，由 GitHub Actions 从打了 tag 的 commit 产出，并附带
`.sha256`。

| 文件 | 内容 |
|---|---|
| [`agentmux-macos-universal.zip`](../../releases/latest) | `AgentMux.app`，同时支持 Intel 与 Apple silicon 的通用二进制 |
| [`agentmux-windows-amd64.zip`](../../releases/latest) | `agentmux.exe` 与安装脚本 |
| [`agentmux-linux-amd64.tar.gz`](../../releases/latest) | 二进制、图标、`.desktop` 条目与 `install.sh` |

构建未做代码签名与公证，二者分别需要 Apple 开发者账号与微软证书。Windows 上选择
"更多信息"再"仍要运行"。macOS 的步骤取决于系统版本：

| macOS 版本 | 步骤 |
|---|---|
| 15 Sequoia 及以上 | 打开后允许其被拦截，然后进入 系统设置 → 隐私与安全性 → 安全性 → **仍要打开** |
| 14 Sonoma 及以下 | 右键（Control 点按）应用 → **打开** → 打开 |
| 任意版本 | 执行 `xattr -dr com.apple.quarantine /Applications/AgentMux.app`，之后正常打开 |

隔离属性由浏览器附加，而非来自压缩包；使用 `curl -L -O <链接>` 下载可避免。

## 开始使用

1. **添加主机。** 地址、用户，以及 ssh-agent / 密钥 / 密码三者之一。支持跳板机。主机
   密钥在首次连接时固定。
2. **创建项目与工作区**——工作区即该主机上的一个工作目录。
3. **添加 agent**：名称，以及启动它的命令。点击 Start。
4. `Ctrl+K` 打开命令面板——连接 agent、打开 shell、安装 CLI、切换主题的最快入口。

| 快捷键 | 作用 |
|---|---|
| `Ctrl/⌘ K` | 命令面板 |
| `Ctrl/⌘ B` | 显示或隐藏左侧树 |
| `Ctrl/⌘ \` | 增加一个窗格——有空闲标签页时直接分屏，否则询问要连什么 |
| `Ctrl/⌘ ⇧ \` | 关闭当前窗格，标签页与其 shell 保持打开 |
| `Ctrl/⌘ ⌥ ←` `→` | 在窗格之间移动焦点 |

## 架构

每台主机一条 SSH 连接并复用：终端、命令与文件传输都是同一条连接上的 channel，因此对同
一台主机开十个终端只做一次认证。空闲连接十分钟后关闭，除非有会话正在持有。

agent 运行在 `tmux` 内的登录 shell 中，而非作为会话自身的进程；因此 agent 退出后留下的
是位于正确目录的可用 shell，而不是被销毁的会话。
